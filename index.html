dtOS — A self-updating personal knowledge base

Inspired by a combo of Karpathy's LLM Wiki post and the AI DB agent OS, this is an MCP-based knowledge base that sits in the background for every claude or chatgpt discussion. Without prompting, it pulls out the key ideas to create a persistent, compounding artifact that constantly gets richer. This artifact can be read as context for each new project, etc. Obsidian is the IDE.

What's built
  • Remote MCP server on Cloudflare Workers — a stateless JSON-RPC server that exposes the wiki to any MCP-capable client (Claude iOS app, claude.ai, etc.), authenticated via a bearer token.
  • GitHub App integration — reads and writes wiki pages directly to a GitHub repo via the GitHub Apps API (JWT signing, cached installation tokens, one commit per tool call), with no local clone needed.
  • Full CRUD tool suite — read tools (get_schema, get_index, get_page, list_pages, search_wiki, get_log, list_raw_sources, get_raw_source) and write tools (create_page, update_page, append_log) that maintain index.md and log.md as side effects.
  • Schema enforcement — frontmatter validation and slug rules (defined in src/schema.ts, with test fixtures for all page types) returned as MCP instructions on initialize so every session picks up wiki conventions automatically.
Takeaways so far
  1. Most useful when scoped to something that is changing regularly but not too broad. I'm using it to collect new ideas and expand on them. I can send it context and it fleshes them out.
  2. Great for bootstrapping claude.md for new projects.
  3. Potential next steps: productize it in a way where others could use it to do something similar.
March, 2026 Archived

RebateGuard — the easiest way to claim heat pump rebates

Inspired by the complexity of claiming my own energy rebate, I built a tool to simplify the process of discovering and claiming heat pump rebates. RebateGuard is a web app that identifies which rebates apply to the user and guides them through the steps to claim it, handling the paperwork on their behalf. The goal was to make it as easy as possible for homeowners to take advantage of energy-saving incentives.

1 / 4
What got built
  • Landing page with ZIP-based utility lookup
  • Intake wizard (location, heating type, timeline, income, etc.)
  • Incentive discovery via Rewiring America API
  • Program rules registry with 4 curated state programs (MA, NY, CA, ME)
  • Crawler infrastructure with deterministic parsing
  • Registry validator (CLI + web UI) with LLM-powered source checking
  • Filing guide generator and workbench
  • Workspace with plan, documents, timeline, and messages pages
  • Risk engine, recommendation scoring, execution step sequencing
Takeaways
  1. Good learning project since it had a large and complex data/crawling component.
  2. Ultimately I built way too much product for the scope of the user problem.
  3. The combo of deterministic rules with LLM-powered source checking and user-facing descriptions proved powerful; this is likely a model I'll use again.
April, 2026 prototype

Opportunity assessment agent debate

Opportunity Agents uses Claude Code multi-agent teams to run structured debates evaluating software business opportunities for solo AI-assisted founders. The idea was to see how effectively a team of agents could work together to identify solo-founder business opportunities.

What was built
  • A multi-agent debate system with four specialized roles (Research Specialist, MBA Strategist, User Research Specialist, CEO/Synthesizer)
  • A structured evaluation rubric scoring opportunities across five dimensions: market size, solo buildability, acquisition simplicity, defensibility, and willingness to pay
  • An output pipeline where each agent writes to their own file and the CEO synthesizes a final ranked assessment
Takeaways
  1. Interesting output, but would take some work to make genuinely useful.
  2. Writing the prompts for the debating agents was the most interesting part.
  3. The multi-agent teams part would be reusable in other contexts.
